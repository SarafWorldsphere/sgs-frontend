# Sample the conversion on the login app

Branch `saas` already contains the login-app code from [01-saas-conversion.md](./01-saas-conversion.md). You build the databases and point `.env.local` at the shared one. You do not paste the host lookup, the role-table rename, or the login branding again.

Section 1 builds the old one-database-per-school shape so you can inspect it with `psql`. Do not start this branch against those databases. Section 2 builds the shared database this branch runs against.

Drop any database left from an earlier attempt before you start. These steps create `sgs_sample`, `sss_sample`, and `saraswati_sample`. They do not use RDS.

```bash
dropdb --if-exists saraswati_local
dropdb --if-exists sgs_sample
dropdb --if-exists sss_sample
dropdb --if-exists saraswati_sample

psql postgres <<'SQL'
SELECT pg_terminate_backend(pid)
FROM pg_stat_activity
WHERE usename = 'swais_app_user'
  AND pid <> pg_backend_pid();

DO $$
BEGIN
    IF EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'swais_app_user') THEN
        IF EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'saraswati_app') THEN
            EXECUTE 'REVOKE saraswati_app FROM swais_app_user';
        END IF;
        EXECUTE 'DROP OWNED BY swais_app_user';
        EXECUTE 'DROP ROLE swais_app_user';
    END IF;
END
$$;
SQL
```

Create the login role. `lib/db.ts` rewrites `PGUSER=postgres` to `swais_app_user`, so the app connects as this role in both setups.

```bash
psql postgres -c "CREATE ROLE swais_app_user LOGIN PASSWORD 'local-only-password' NOSUPERUSER NOBYPASSRLS;"
```



## 1. Old way — one database per school

SGS data lives in `sgs_sample`. SSS data lives in `sss_sample`. The tables use the `sgs_` and `sss_` prefixes. Branch `saas` does not query those names, so this section stops at the databases.

Create both databases and the tables the email check reads.

```bash
createdb sgs_sample
createdb sss_sample
```

```bash
psql sgs_sample <<'SQL'
CREATE TABLE sgs_student_master (
    student_id    bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    full_name     text,
    student_email text,
    student_phone text
);
CREATE TABLE sgs_teacher_master (
    teacher_id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    full_name  text,
    email_id   text,
    phone      text
);
CREATE TABLE sgs_parent_master (
    parent_id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    full_name text,
    email     text,
    phone     text
);
CREATE TABLE sgs_users_masters (
    user_id   bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    full_name text,
    email_id  text,
    mobile_no text
);
INSERT INTO sgs_student_master (full_name, student_email)
VALUES ('SGS Student', 'sgs.student@example.com');
GRANT SELECT ON sgs_student_master, sgs_teacher_master, sgs_parent_master, sgs_users_masters TO swais_app_user;
SQL
```

```bash
psql sss_sample <<'SQL'
CREATE TABLE sss_student_master (
    student_id    bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    full_name     text,
    student_email text,
    student_phone text
);
INSERT INTO sss_student_master (full_name, student_email)
VALUES ('SSS Student', 'sss.student@example.com');
GRANT SELECT ON sss_student_master TO swais_app_user;
SQL
```

Confirm the two schools are in two databases:

```bash
psql sgs_sample -c "SELECT full_name, student_email FROM sgs_student_master;"
psql sss_sample -c "SELECT full_name, student_email FROM sss_student_master;"
```

The first returns `sgs.student@example.com`. The second returns `sss.student@example.com`. A query for `sgs_student_master` on `sss_sample` fails, because that database has `sss_student_master`.

## 2. New way — one database, school from the host

Drop the two school databases. Create one database and apply `saraswati-tenant-kit` (`src/`, then `migrations/`).

```bash
dropdb sgs_sample
dropdb sss_sample
createdb saraswati_sample
```

From `saraswati-tenant-kit folder`, as the database owner:

> ```bash
> DATABASE_URL=postgresql://localhost/saraswati_sample ./scripts/apply.sh 
> psql saraswati_sample -c "GRANT saraswati_app TO swais_app_user;"
> ```

Insert both schools and one student each. The domain is the host the browser will use. Seed the students as the owner, inside `set_config`, because row-level security is already on.

`/etc/hosts`:

```text
127.0.0.1 sgs.localhost sss.localhost
```

connect to psql `psql saraswati_sample` 

```sql
INSERT INTO platform.tenants (tenant_id, slug, status, isolation, config)

SELECT set_config('app.tenant_id', '22222222-2222-2222-2222-222222222222', true);
INSERT INTO student_master (full_name, student_email)
VALUES ('SSS Student', 'sss.student@example.com');

```

As `swais_app_user`, with no `app.tenant_id` set, this returns zero rows:

```bash
psql "postgresql://swais_app_user:local-only-password@localhost/saraswati_sample" \
  -c "SELECT full_name, student_email FROM student_master;"
```

The login-app files are already on branch `saas`: `lib/school.ts`, `proxy.ts`, `lib/db.ts`, the table names in `lib/role-mapping.ts`, `app/public/tenant-config/route.ts`, and `SchoolBrand` on the login page. Check out that branch and set the environment below. The code blocks that used to be copied by hand are in [01-saas-conversion.md](./01-saas-conversion.md) under "Same two calls in every module", for the other apps.

```bash
git checkout saas
npm install
```

`.env.local`:

```bash
PGHOST=localhost
PGPORT=5432
PGUSER=swais_app_user
PGPASSWORD=local-only-password
PGDATABASE=saraswati_sample
SARASWATI_DATABASE_URL=postgresql://swais_app_user:local-only-password@localhost:5432/saraswati_sample
SARASWATI_PUBLIC_PROTO=http
AUTH_URL=http://sgs.localhost:3000
```

Start the app again. The pool in `lib/db.ts` is created once per process, so a process started against `sgs_sample` or `sss_sample` keeps that database until you stop it.

```bash
npm run dev
```
